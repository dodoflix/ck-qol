# Core Keeper QoL

Client-side quality-of-life tweaks for Core Keeper, bundled as one PugMod mod so
they share a single config file and a single install.

Settings live in the game's own menu: **Settings → QoL settings**.

Targets Core Keeper **1.2.1.5** (Unity 6000.0.59f2).

## Install

```sh
./check.sh     # compile against the game's assemblies, and lint
./install.sh
```

Close the game first — mods are compiled at startup, so a running client will not
pick up changes.

`install.sh` deploys to `CoreKeeper_Data/StreamingAssets/Mods/CkQol/` inside the
game install. Set `CK_GAME_DIR` if your install lives elsewhere.

> Steam can wipe `StreamingAssets/` on game updates and on Verify Integrity.
> Re-run `install.sh` if the mod stops loading after either.

## How it works

PugMod ships **C# source**, not a compiled DLL — the game carries Roslyn and
compiles mods in-process at startup. There is no build step, and mistakes surface
in `Player.log` after a full launch.

`check.sh` exists to close that gap. It compiles the source against
`CoreKeeper_Data/Managed/`, then lints for APIs that PugMod's **security
verifier** rejects — `System.Reflection` above all. A clean compile says nothing
about passing the verifier, and the only symptom in game is a bare
"Compilation failed", so run it before every install.

`ModManifest.json` is generated by `install.sh` from whatever is in `src/`:
PugMod silently ignores any `.cs` not listed in the manifest, which is
indistinguishable from a feature that does not work.

## The settings menu

The mod does not draw its own UI. It **clones the game's real option rows** and
swaps in its own behaviour, so navigation, fonts, sounds and controller support
come from the game rather than being imitated.

Things worth knowing before touching `Native/`:

- Menus are **SpriteRenderer world-space UI** driven by `RadicalMenu`, not uGUI.
- Rows live under a **container inside the menu**, not under the menu root. That
  container carries an offset, so a row parented to the root gets the correct
  local position from the layout and the wrong world position — far below the
  visible list. Clone with `parent: null` to land beside the donor.
- `RadicalMenu.menuOptions` is filled in `Awake` **only**, and the option menus are
  instantiated inactive, so that list is empty at startup. Read rows with
  `GetComponentsInChildren` instead.
- `UpdatePosition` ignores `autoPositioning` and always lays out, but menus that
  never auto-position ship with `menuEntryVirtualHeight` at zero, which stacks
  every row on one line. Give it a measured pitch.
- `extraVerticalSpacing` is public on every row and is subtracted before the row
  is placed. A clone inherits the donor's group-separator gap and lands low.
- `PugText.Render` treats its argument as a **localization key** unless
  `localize` is false, and early-outs unless `force: true`.
- Donor rows are matched by shape (`isOnOffToggle`, type test), never by class
  name, so renamed game options do not break the mod.

## Adding a feature

Create a class in `src/Features/` extending `QolFeatureBase`:

```csharp
public class MyTweak : QolFeatureBase
{
    public override string Name => "MyTweak";
    public override string Description => "Shown as the config section comment.";

    private readonly FloatSetting _strength =
        new FloatSetting("Strength", "Strength", 1f, 0f, 5f, "Tooltip text.");

    public override IEnumerable<ModSetting> GetSettings()
    {
        yield return _strength;
    }

    public override void Update()
    {
        // Read .Value at point of use - that is what makes menu edits apply live.
        DoSomething(_strength.Value);
    }
}
```

Register it in `CkQolMod.BuildFeatures`:

```csharp
yield return new Features.MyTweak();
```

It then gets its own page, an Enabled toggle, a config section named after
`Name`, and a row per setting.

| setting | row |
|---|---|
| `BoolSetting` | toggle, shows `on` / `off` |
| `IntSetting`, `FloatSetting` | slider, using min/max |
| `ChoiceSetting` | slider across the options, stored by name so reordering them cannot change anyone's setting |

Two rules:

- **Read `.Value` at point of use, not at init.** Caching it means menu edits do
  nothing until restart.
- **`Name` is the config key.** Renaming it orphans users' existing settings.

Features are isolated: one that throws in any lifecycle callback is logged,
disabled, and the rest keep running.

## Scope

Client-side only, `requiredOn: 1`. No server install, and other players do not
need it. Anything that changes world state, spawns entities authoritatively, or
drives world generation is server-authoritative and out of scope.
